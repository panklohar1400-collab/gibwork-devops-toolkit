# Gibwork DevOps Toolkit

A terminal-first developer workflow tool for reviewing repository maintenance markers and turning confirmed issues into a structured bounty draft. It is intentionally not a web application.

## Why it is useful

Project maintainers often find unfinished work scattered across repositories and then manually convert it into actionable tasks. This tool performs a repeatable local scan, produces a reviewable report, and prepares a bounty brief with acceptance criteria and verification steps. A separate command connects to the official Gibwork CLI to inspect available tasks.

## Requirements

- Node.js 22 or newer
- `@gibwork/cli` only for the `bounties` command and CLI health check

## Quick start

```bash
# Run the local scanner; no wallet or network access required
node src/cli.js triage ./your-repository --out ./gibwork-output

# Generate a bounty-ready draft as well as the triage reports
node src/cli.js brief ./your-repository --out ./gibwork-output --title "Resolve confirmed validation issues"

# Check the local environment
node src/cli.js doctor

# Install the official CLI if you want to discover live tasks
npm install --global @gibwork/cli
node src/cli.js bounties --page 1 --limit 10

# Run automated tests
npm test
```

You can also link this package locally with `npm link` and use the `gibtriage` command.

## Output

The output directory contains:

- `triage-report.json` — machine-readable findings, counts, scan time, and warnings.
- `triage-report.md` — human-readable repository report.
- `bounty-brief.md` — generated by `brief`; a proposal draft with scope, acceptance criteria, verification plan, and sample findings.

## Design and safety decisions

- Local scanning does not need a wallet, API key, or network connection.
- The scanner skips common dependency/build folders, environment files other than `.env.example`, unsupported extensions, and files larger than 1 MB.
- The scan is bounded to 20,000 entries by default to avoid runaway traversal.
- Findings are leads, not automatic bug diagnoses; a developer should confirm them before creating a bounty.
- The `bounties` command invokes `gibwork` with an argument array rather than a shell command string and prints the CLI's JSON response.
- The project does not create bounties, submit work, sign transactions, or move funds automatically.

## Commands

```text
gibtriage triage [directory] [--out directory]
gibtriage brief [directory] [--out directory] [--title "Bounty title"]
gibtriage bounties [--page N] [--limit N]
gibtriage doctor
```

## Example workflow

1. Run `triage` on a repository you maintain.
2. Review `triage-report.md` and confirm which markers represent real work.
3. Run `brief` to prepare the initial bounty draft.
4. Edit the scope and acceptance criteria based on the actual issue.
5. Use the official Gibwork CLI or MCP flow to publish or manage a bounty only after reviewing the details and any payment quote.

## Limitations

This first version detects explicit source markers; it does not claim to perform static analysis, infer severity with AI, or automatically estimate a reward. Binary files, generated directories, unsupported file types, and large files are intentionally skipped. Scan warnings should be checked before treating a report as complete.
